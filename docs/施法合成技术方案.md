# 多页面代码法阵与施法合成技术方案

## 1. 目标

在现有 C／Python 代码转法阵项目中增加施法合成体验：用户可使用摄像头、照片或本地视频识别张开的手掌，把选定法阵沿掌心朝外方向分层放置，并以透视方式叠加到媒体画面。导出支持 PNG 静帧，不包含视频导出。

首版支持当前代码生成的法阵，以及包含项目分层元数据的动态 SVG。无分层元数据的旧 SVG 作为单层素材导入。媒体在浏览器本地处理，不上传服务器。

## 2. 页面结构

使用三个独立页面，通过顶部导航切换。采用 Hash 路由，以支持浏览器前进、后退和直接访问，无需服务器配置路径回退。

| 页面 | 路由 | 内容 |
| --- | --- | --- |
| 代码炼成 | `#/forge` | C／Python 编辑、生成法阵、查看图层、运行高亮与 SVG 导出 |
| 法阵播放 | `#/player` | 导入项目 SVG、播放动画、定位时间及查看图层 |
| 施法合成 | `#/cast` | 摄像头／照片／视频输入、手部跟踪、三维合成与 PNG 导出 |

默认页为“代码炼成”。共享状态保存当前代码、解析模型、法阵设置及导入 SVG。用户可从代码页或 SVG 播放页将当前素材带入施法页。跨页保留编辑内容、页面参数和滚动位置；刷新后恢复默认样例，不持久化用户代码、照片或视频。

页面各自管理播放实例。切换页面时暂停非活动页面动画；离开施法页时停止摄像头、检测任务并释放 GPU 资源。返回施法页可以恢复媒体预览，但摄像头需由用户再次开启。

## 3. 手部识别与姿态估计

### 3.1 关键点检测

使用 `@mediapipe/tasks-vision` 的 Hand Landmarker。照片使用 IMAGE 模式，视频帧和摄像头使用 VIDEO 模式。检测放在 Web Worker 中运行，避免阻塞界面。MediaPipe 可输出图像坐标、手部世界坐标和左右手类别；同步处理逐帧视频时应传入媒体时间戳。模型与 WASM 随项目部署，媒体不上传。

最多检测两只手，法阵只绑定一只施法手。默认选择面积较大的手，允许用户切换，并通过手别和位置连续性减少双手交叉时的切换。

### 3.2 掌心坐标系

主要使用手腕（0）、食指根部（5）、中指根部（9）、无名指根部（13）和小指根部（17）：

- 掌心位置：掌根关键点的加权中心。
- 横轴 `U`：小指根部至食指根部。
- 纵轴 `V`：手腕至中指根部。
- 法线 `N`：由 `U × V` 计算并正交化，使 `U、V、N` 成为稳定的掌心坐标系。

法阵平面平行于掌面，沿掌心朝外的法线排列。法线正反向存在歧义；结合左右手类别和前后帧连续性确定初始方向，并提供“翻转施法方向”校正按钮。

### 3.3 张掌判断与跟踪状态

根据指节夹角与相对掌宽的距离判断手指是否伸展。采用张开／收起滞回阈值和连续帧确认，避免状态闪烁。张开时法阵渐显，收起时渐隐。短暂丢失检测时保持最后姿态约 200ms 后淡出；重新识别时平滑恢复。照片允许手动启用法阵、移动锚点和校正方向。

位置和尺寸使用时间相关的平滑滤波，朝向使用四元数插值。长时间丢失、重投影误差过大或掌面估计退化时，不强行跳转到不可信姿态。

## 4. 三维定位与透视投影

### 4.1 相机假设

建立统一的透视相机，垂直视场角默认 50°，主点位于画面中心，允许手动调整视场角。像素近似方形时，焦距以像素计为：

```text
fy = H / (2 × tan(FOVy / 2))
fx = fy
```

单目媒体无法唯一确定真实焦距、手的真实尺寸和绝对距离，因此以掌宽作为相对世界单位，通过重投影误差拟合手的旋转和平移，并提供人工校正。效果保证同一虚拟相机内透视一致，不宣称厘米级测量精度。

将归一化的三维手形 `Qj` 投影到与之对应的二维关键点 `pj`，求解旋转 `R` 和平移 `T`：

```text
最小化 Σ robustError(project(K, R × Qj + T) - pj)
```

使用掌根点作为主要约束，对可能被遮挡的指尖降低权重；上一帧解用作下一帧初值。相机坐标与 Three.js 坐标之间显式转换。镜像只在画面显示映射中处理一次，避免手别和施法方向重复反转。

### 4.2 法阵分层摆放

设掌心位置为 `P`，朝外法线为 `N`，首层距离为 `d0`，第 `i` 层的累计距离为 `di`：

```text
Pi = P + (d0 + di) × N
X  = Pi + x × U + y × V
```

每个独立层是掌面平行的空间平面。中环靠近掌心，其余主层沿法线向外排列。副环归属其主环，不额外拆成深度层，继续执行原有公转。层顺序可在界面调整。

最终层距由产品后续指定。开发预览初值为首层距离 0.5 个掌宽、相邻层距 0.5 个掌宽，均可调。

相机投影采用：

```text
screenX = fx × X / Z + cx
screenY = fy × Y / Z + cy
```

所有层共享同一投影矩阵。距离相机更近的层自然更大；倾斜平面自然出现压缩。正视共轴层仍可能重叠，这是透视投影的结果；不通过人为错开来假造深度。提供辅助侧视图检查层距，但不改变主合成结果。

## 5. 法阵素材与动画

### 5.1 统一分层素材接口

建立 `MagicLayerSource` 接口，向施法页面提供稳定层 ID、层顺序、局部边界、透明 SVG 内容和指定时间的动画帧。合成器无需了解底层来自 C、Python 还是 SVG。

### 5.2 当前法阵与导入 SVG

当前代码法阵从模型提取未应用旧二维叠层变换的独立图层，保留符文布局、旋转方向和周期、表针、运行高亮与副环公转。

导入项目 SVG 时复用现有安全读取及动画记录，按分层元数据提取图层，播放运动和执行轨迹，不还原源代码。无层元数据的 SVG 以单层素材导入，并提示无法恢复原分层。

移除每层共享画布背景和副环的深色遮盖填充，保留描边与符文内容，以透明纹理叠加至照片或视频。

### 5.3 WebGL 合成

首版将每层透明 SVG 栅格化为纹理，再映射至 Three.js 中的独立平面。纹理预览以 1024px 为起点，根据投影尺寸提升至 2048px；总纹理像素达到预算时降低分辨率。PNG 导出时生成高分辨率纹理。

姿态渲染与 SVG 纹理更新时间分离，纹理更新采用限速、最新请求优先和过期结果丢弃。使用透明混合和深度顺序进行合成；轻量辉光可调，不能遮蔽符文细节。

## 6. 媒体时间与导出

- **照片**：检测一次并固定姿态；法阵动画独立播放，导出所选时刻。
- **视频**：法阵时钟跟随 `currentTime`；暂停同步暂停，定位后重新处理当前帧并重置跟踪滤波器；检测繁忙时丢弃旧帧，只处理最新帧。
- **摄像头**：使用单调时钟播放。用户关闭、切换输入或离开页面时释放摄像头轨道、Worker、纹理和对象 URL。
- **PNG**：冻结当前媒体帧、手部姿态和法阵时间，合成后导出。照片按原图尺寸输出；视频和摄像头导出当前帧。超出浏览器纹理限制时等比例缩小并提示，不静默裁切。

媒体画面、识别坐标和 WebGL 画布共享同一尺寸、裁切和镜像变换，默认完整显示原画面。

## 7. 页面布局

施法页主区域用于媒体与合成预览，侧边控制区分为三个标签：

- **输入与素材**：摄像头、照片、视频，以及代码法阵／项目 SVG 选择。
- **空间与透视**：尺寸、离掌距离、层距、层顺序、视场角和方向修正。
- **跟踪与输出**：施法手、检测状态、可选关键点调试、手动锚点与 PNG 导出。

播放控制位于预览底部。窄屏时控制区移至预览下方。代码编辑和普通 SVG 播放仍在独立页面中。

## 8. 实施顺序

1. 增加三页导航与共享素材状态，验证直接访问、前进／后退和页面状态保留。
2. 用手动位置和朝向实现照片上的三维分层、透视、透明合成与 PNG 导出。
3. 接入照片手部识别、张掌判断、自动姿态拟合和手动校正。
4. 接入摄像头和视频 Worker、平滑跟踪、丢失恢复与媒体时间同步。
5. 接入动态 SVG 分层，优化纹理预算和资源回收，完成回归。

## 9. 验收标准

- 页面可直接访问，浏览器前进／后退正常，跨页编辑内容保留，切页无自动滚动。
- 离开施法页后摄像头停止，检测和动画不在后台继续运行。
- 左右手、镜像、窗口缩放和不同画面比例下，掌心锚点与方向一致。
- 近远缩放、平面倾斜和层深投影符合统一相机模型；正面允许合理重叠，斜视可辨前后层距。
- 张掌、握拳、短暂遮挡、快速移动和双手交叉时状态不闪烁或任意跳变。
- 视频暂停、回退和定位后，法阵时间与视频帧一致。
- 当前生成法阵与导入 SVG 保留相应图层动画；旧 SVG 缺层信息时按单层处理。
- PNG 导出与预览在位置、方向、镜像、时间和画面裁切上相符。
- 现有 C／Python 解析、符文高亮、表针动画和 SVG 播放不退化。

## 10. 首版边界

首版不做人物或场景深度识别、不实现手指／人物对法阵的真实遮挡、不导出视频，也不保证恢复真实厘米距离。严重遮挡、运动模糊或掌面近乎侧向时，允许提示用户校正或暂时隐藏法阵。
